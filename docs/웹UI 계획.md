## 한 줄 요약
볼트에 웹 UI를 붙이는 단계별 계획 — 무엇을 만들고 무엇은 만들지 않는가, 그리고 왜 그 순서인가.

> [!important] 지켜야 할 원칙
> 루트 `CLAUDE.md`의 **"도구를 추가할 때"** 조항이 이 계획 전체를 구속한다.
>
> 1. **파일이 정본이다** — 도구가 만드는 상태도 전부 파일
> 2. **규칙을 코드에 복사하지 않는다** — `SKILL.md`를 읽어서 쓴다
> 3. **도구를 꺼도 Obsidian·git·Claude Code가 그대로 동작한다**

---

# 왜 만드나 — Obsidian이 못 하는 것만

| 기능 | Obsidian | 웹 UI가 필요한가 |
|---|---|---|
| **페이지 읽기·검색** | ✅ 더 나음 | ⚠️ **읽기만 만든다** (아래) |
| 편집 | ✅ 압도적 | ❌ 만들지 않는다 |
| 그래프 | ✅ 압도적 | ❌ **버튼으로 Obsidian을 연다** |
| **lint 실행** | ❌ 불가 | ✅ |
| **인제스트 실행** | ❌ 불가 | ✅ |
| **query** | ❌ LLM 없음 | ✅ |
| **자료 넣기 폼** | 파일 복사만 | ✅ 폼이 편함 |

**"위키를 보는 도구"가 아니라 "작업을 실행하는 도구"다.** 편집·그래프를 다시 만들면 손해다.

## 읽기는 왜 넣었나

처음엔 "Obsidian이 더 나으니 만들지 말자"고 했으나, **한 작업 안에서 마찰이 생겼다.**
lint가 "이 페이지에 문제가 있다"고 알려줘도 클릭해서 볼 수 없으면 Obsidian으로 넘어가야 한다.
다른 PC에서 작업할 때는 더 그렇다.

그래서 **읽기 전용 뷰어 + 검색**을 넣고, 편집이 필요하면 `obsidian://` 링크로 **넘긴다.**
두 도구를 따로 운영하는 대신 **이어붙이는** 방식이다.

---

# 0단계 — 전제 조건 (웹 UI보다 먼저)

수집이 **다른 PC에서** 일어나므로, 동기화가 없으면 웹 UI가 반쪽이 된다.
그 PC에서 모은 자료를 이 PC의 서버가 볼 수 없기 때문이다.

- [ ] **Zotero Sync 켜기** — 무료(첨부 300MB). 논문·서지정보 자동 동기화
- [ ] **볼트 동기화 결정** — Obsidian Sync($4/월) 또는 Syncthing(무료)
  - 두 PC가 동시에 켜져 있는 시간이 적으면 → Obsidian Sync
  - 많으면 → Syncthing

> **이걸 건너뛰면 웹 UI를 만들어도 "이 PC의 자료만" 보인다.**

# 1단계 — 상태판 + lint + 자료 넣기 (LLM 0회)

`python tools/lint.py`가 이미 있어 대부분 배선이다.

## 만들 것

- [ ] `tools/server.py` — FastAPI 골격. 실행은 `python tools/server.py`
- [ ] `tools/static/index.html` — 화면 한 장
- [ ] **화면 A 상태판** — 페이지·원본·미인제스트·보강대기·stable 수, 축별 분포
- [ ] **화면 B 자료 넣기** — 드래그 업로드 + Zotero 서지정보 가져오기 + 폼
- [ ] **화면 C 점검** — lint 실행 버튼 + **조치 카드** + `[오탐]` 버튼
- [ ] **화면 D 위키** — 읽기 전용 뷰어 · 전체 검색 · 백링크 · `obsidian://` 열기
- [ ] **Obsidian 열기 버튼** — 그래프는 자체 구현 대신 Obsidian으로 넘긴다
- [ ] `queue.md` — 인제스트 대기열
- [ ] `lint-ignore.json` — 오탐 표시 기록

## 화면 B가 2단계의 입력이다

여기서 **인제스트에 필요한 답을 미리 받는다.**

| 받을 것 | 지금 어디서 |
|---|---|
| `why` 왜 담았나 | 클리퍼에서 받음 |
| `axis` 축 | 클리퍼에서 받음 |
| 주제 태그 | 기존 태그를 후보로 제시 |
| **지금 하는 일과 연결** | 현재 `/ingest` 질문 2 |
| **용도** (참고/논문/강의) | 현재 `/ingest` 질문 3 |

**질문을 인제스트 시점에서 수집 시점으로 옮기는 것**이 2단계 자동화의 전제다.

## 완료 기준

- 브라우저에서 볼트 상태를 확인할 수 있다
- lint를 버튼으로 돌리고 결과를 카드로 본다
- PDF를 끌어놓으면 `raw/papers/*.md`가 우리 frontmatter 형식으로 생긴다
- **서버를 꺼도 아무것도 안 깨진다**

# 2단계 — 자동 인제스트 + 리뷰 큐 (LLM 사용)

## 만들 것

- [x] 4단계 파이프라인 — `tools/ingest.py` (읽기 → 분석 → 작성 → 마무리)
- [x] **진행 표시** — 단계 네비. 진행 상황은 `reports/ingest-<id>.json`이 정본
- [x] **분석 미리보기** — 요약·축 검증·갱신 대상·새 페이지 후보·모순 건수
- [x] `wiki/review.md` — 리뷰 큐
- [x] 규칙 로딩 — 6개 규칙 파일(38KB)을 **읽어서** 시스템 프롬프트로
- [x] **제공자 계층** — `tools/llm.py`. OpenRouter 기본, Anthropic도 가능

## 제공자를 왜 분리했나

키가 없으면 2단계가 통째로 멈춘다. **OpenRouter는 키 하나로 여러 모델을 쓴다** —
Claude·GPT·Gemini·오픈 모델까지. 나중에 로컬 LLM으로 옮겨도 `llm.py`만 고치면 된다.

키는 **환경변수에서만** 읽는다. 볼트는 git에 올라가므로 파일에 두지 않는다.

## 실행 결과 (2026-09-05, 논문 1건)

| | |
|---|---|
| 모델 | `z-ai/glm-5.3-flash` |
| 토큰 | 입력 43K · 출력 17K |
| 비용 | **$0.0074** |
| 시간 | 약 5분 |

분석이 정확했다 — 축 일치 판정, 갱신 대상 1개 지목, 새 페이지 후보는
생성 기준 미달로 **보류**하고 리뷰 큐로 보냈다. 편집안은 순수 추가(+14줄/-1줄)였다.

## 실행하며 고친 것

| 문제 | 원인 | 조치 |
|---|---|---|
| JSON 파싱 실패 | `json_object` 모드에서 모델이 산문을 뱉음 | **`json_schema`로 형식 강제** |
| 가짜 분석 결과 통과 | 빈 응답을 복구 재시도에 넘겨 "텍스트가 없다"는 답이 스키마에 맞춰짐 | 빈 응답은 실패로 처리 |
| 조용한 품질 저하 | 스키마 실패 시 맨몸 호출로 내려감 → YAML 출력 | 맨몸 fallback 제거 |
| 멈춘 호출 무한 대기 | 타임아웃 없음 | `LLM_TIMEOUT` |
| 실패 원인 소실 | 응답 원문을 안 남김 | 보고서에 `raw` 저장 |

## 자동으로 넘기지 않는 것 (리뷰 큐로)

| 상황 | 근거 |
|---|---|
| 기존 페이지와 **모순** | `wiki/CLAUDE.md`: "네가 판정하지 마라" |
| **`axis` 불일치** | 실제로 2건 발생했다 |
| **생성 기준 애매** | 참조 3곳·근거 1,200B 근처 |
| **`cite_key` 확정** | `raw/CLAUDE.md`: "제안하고 확인받은 뒤" |

리뷰 큐는 **인제스트를 막지 않는다.** 나중에 편할 때 처리한다.

## 작업 타입을 제한한다

큐에 담기는 조치는 **미리 정한 것만** 쓴다 — `페이지 생성` / `자료 수집` / `건너뛰기` / `모순 판정`.
LLM이 임의 작업을 만들어내지 못하게 막는 장치다.

## 완료 기준

- 자료를 넣고 [인제스트]를 누르면 질문 없이 끝까지 진행된다
- 판단이 필요한 것만 리뷰 큐에 쌓인다
- **터미널의 `/ingest`도 그대로 동작한다**

# 3단계 — query

## 만들 것

- [x] 질문 입력 + 답변 표시 — `tools/query.py`
- [x] `index.md` → 후보 선정 → 페이지 최대 4개 읽기 (2단계 검색)
- [x] **`status` 배지** — `stable` 초록 / `draft` 주황 / `seed` 빨강
- [x] 출처 링크 — **뷰어에서 바로 열린다** (Obsidian으로 안 넘어가도 됨)
- [x] Knowledge Flywheel — `Output/` 저장 시 `derived: true`
- [x] **유령 링크 검사** — 읽지 않은 페이지를 링크하면 경고

## 실행 결과 (2026-09-05)

질문: "프롬프트 인젝션이 무엇이고 어떻게 막나?"

| | |
|---|---|
| 고른 페이지 | 3개 (전체 15개 중) |
| 토큰 | 입력 22K · 출력 18K |
| 비용 | **$0.0062** |
| 시간 | 약 4분 |

답변이 규칙을 지켰다.
- 근거 3개 모두 `draft` → **"검증이 필요하다"를 먼저 명시**
- 출처 2개 교차 확인분과 **1개뿐인 서술을 표로 구분**
- 원문 서술과 **필자 추론(출처 없음)을 구분**
- SQL 인젝션과의 비교 예시 제시

## 여기서도 검사가 오류를 잡았다

모델이 `[[AI보호) 프롬프트 인젝션]]` 처럼 **여는 괄호를 빠뜨렸다.**
Obsidian에서 열리지 않는 깨진 링크다. 축 접두어를 기계적으로 복구하고,
그래도 남는 것은 "읽지 않은 페이지를 링크했다"고 화면에 경고한다.

## 하지 말 것

**검색 엔진으로 대체하지 마라.** 참고한 `Raymonda/LLM-WIKI`는 `QueryView.vue`가 204바이트로 비어 있고 Elasticsearch 검색이 그 역할을 흡수했다.
그러면 **`status` 기반 인용 강도가 사라진다** — 논문 목표에 직결되는 장치다.

# 만들지 않을 것

| | 왜 |
|---|---|
| MySQL·Elasticsearch | 위키 전체가 32K 토큰. 마크다운이 DB로 가면 Obsidian·git과 단절 |
| Docker 스택 | 개인 볼트에 과잉 (참고 프로젝트는 RAM 2.5~4GB) |
| 다중 사용자·권한·감사 로그 | 혼자 쓴다 |
| 그래프 뷰 | Obsidian이 더 낫다 |
| **편집 기능** | Obsidian이 압도적. 웹에서 편집하면 충돌 관리가 생긴다 |
