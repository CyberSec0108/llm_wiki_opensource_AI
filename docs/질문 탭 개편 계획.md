# 참고한 것

`Sec_AI`는 KISA 보안 감사 가이드에 답하는 채팅 UI다. 3열 레이아웃(대화 이력 · 대화창 · 출처 서랍), `EventSource` 기반 실시간 스트리밍, 단계별 진행 표시, 번호 인용(`[1][2]`) 클릭 이동, 자체 제작 화이트리스트 마크다운 렌더러(`restricted-markdown.js`, 815줄, 의존성 0)를 갖췄다.

**색감·레이아웃을 그대로 베끼지 않는다.** 기업용 보안 감사 툴의 네이비/블루 팔레트이고, 우리 톤(연한 배경 · `--acc` 파랑)이 이미 자리잡았다. 가져오는 것은 **기능과 패턴**이지 디자인이 아니다.

# B안 — 구조 변경 필요 (결정 필요)

## 걸리는 지점 — 실시간 스트리밍

Sec_AI는 `EventSource`로 토큰 단위 스트리밍한다. 우리 답변 호출은 **`json_schema`로 통째로 강제**한다 — `answer`+`sources`+`missing`이 한 JSON 덩어리라, JSON이 완성되기 전엔 화면에 보여줄 수 없다. 이것이 지금 "4분간 안 움직이는" 원인이다.

| 방식 | 설명 | 트레이드오프 |
|---|---|---|
| 가짜 진행률 (A안에 포함) | 답변은 한 번에 받되, 화면엔 단계 표시만 애니메이션 | 실제 스트리밍 아님. 구현 쉬움 |
| 진짜 스트리밍 | 답변 텍스트만 먼저 스트리밍(스키마 없이) → 짧은 2차 호출로 출처만 구조화 추출 | 호출 1회 추가. `tools/query.py` 재설계 필요 |

**결정 기준:** A안(가짜 진행률)을 써보고도 4분 대기가 실제로 불편하면 그때 진행한다.

# Sec_AI 형태로 맞춘 2차 수정 (2026-09-05)

사용자가 스크린샷으로 "아직 Sec_AI와 많이 다르다"고 지적한 것들.

## 첫 토큰이 늦는 문제 — 원인을 측정으로 확정했다

스트리밍 청크를 직접 계측했다.

```
 0.0s  청크    1개 (content 0) reasoning=The…
10.4s  청크  324개 (content 0) reasoning=소…
40.5s  청크 1196개 (content 0) reasoning=록…
47.4s  *** 첫 CONTENT 토큰 *** (청크 1437개째)
```

**청크는 계속 오고 있었다. 전부 모델의 "생각"(`delta.reasoning`)이었고,
실제 답변은 47초 뒤에 시작됐다.** 진행 표시가 다 끝났는데도 화면이
멈춘 것처럼 보였던 이유다. 편차도 크다 — 같은 프롬프트로 7.7초인 적도 있다.

세 가지로 대응했다.

| | |
|---|---|
| **생각을 보여준다** | `delta.reasoning`을 `reasoning` SSE 이벤트로 흘려보내고, 접을 수 있는 상자에 실시간 표시. 답변이 시작되면 자동으로 접히고 "모델의 생각 47초 (눌러서 보기)"로 남는다 |
| **생각을 줄인다** | `.env`의 `LLM_REASONING=low` — OpenRouter의 `reasoning.effort`. `low`로 시작한다. `none`이면 아예 끈다 |
| **무한 대기를 막는다** | `LLM_FIRST_TOKEN_TIMEOUT=180`. 스트리밍 응답은 연결이 열려 있는 한 SDK 타임아웃이 안 걸린다 — 실측에서 340초를 기다려도 아무 오류가 안 났다 |

## cmd에 찍히던 ConnectionResetError

클라이언트가 새로고침·탭 이동으로 떠나도 서버가 그걸 몰라서, 죽은 소켓에
쓰려다 난 오류였다. 이제 1초마다 `request.is_disconnected()`를 확인하고,
**떠난 것을 중단 버튼과 똑같이 처리한다** — 오류도 사라지고 아무도 안 보는
LLM 호출에 요금이 나가는 것도 막는다.

## Sec_AI 형태로 맞춘 것

| | 이전 | 지금 |
|---|---|---|
| 진행 표시 | 가로 막대 3칸 | **세로 목록 + 동그란 마커** (pending → active 맥박 → done 초록), 제목에 shimmer |
| 출처 표기 | 한 줄 나열 | **카드** — `[번호] 제목` / 메타 한 줄 / `위키에서 열기 →` |
| 예시 질문 | 화면 맨 위 | **입력창 바로 위** |

색은 우리 팔레트를 그대로 쓴다 — 구조와 동작만 맞췄다.

## 결과 — 3배 빨라졌다

`reasoning=low`를 **스트리밍 호출에만** 적용한 뒤 실측:

```
  0.0s  질문 확인
 14.4s  위키 후보 찾기 (후보 4쪽)
 14.4s  답변 작성 시작
 17.2s  *** 첫 토큰 ***  ← 답변 작성 단계 시작 후 2.8초
 41.3s  완료 (토큰 1,735개, 입력 39.8K / 출력 2.3K)
```

| | 이전 | 지금 |
|---|---|---|
| 첫 토큰까지 | 47초 (최악 340초+ 무한대기) | **2.8초** |
| 전체 완료 | 123.8초 | **41.3초** |

주의 — `effort`를 명시하면 **간단한 호출은 오히려 느려진다.** 실측에서
스키마 호출은 미설정이 추론 토큰 1개인데 `low`는 206개였다. 그래서
후보 선정·출처 추출 같은 스키마 호출에는 걸지 않고, 답변을 길게 쓰는
스트리밍 호출에만 적용한다.
