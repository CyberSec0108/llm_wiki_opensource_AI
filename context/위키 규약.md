## 한 줄 요약
볼트 전체에서 공유하는 값의 정의 — 폴더 지도, `type`, `status`, 파일명. 폴더별 작업 규칙은 각 폴더의 CLAUDE.md에 있다.

## 폴더 지도

| 폴더 | 계층 | 성격 |
|---|---|---|
| `raw/` | 원본 | 불변. 추가만 가능 |
| `wiki/` | 파생 | AI가 컴파일·유지. 재생성 가능 |
| `Output/` | 결과물 | 위키를 근거로 만든 산출물 |
| `context/` | 메타 | 나에 대한 정보. 필요할 때만 읽힘 |
| `wiki/_archive/` | 폐기 | 완전히 대체된 페이지. 근거로 인용하지 않는다 |
| `templates/` | 도구 | 새 파일 시작용 |
| `docs/` | 문서 | 시스템 설계 설명. 규칙이 아니라 규칙의 배경 |
| `tools/` | 도구 | `lint.py` — 규칙을 코드로 옮긴 검사기 |
| `reports/` | 생성물 | lint 결과. 파생물이라 git 추적 안 함 |

주제별로 폴더를 쪼개지 않는다. 분류는 폴더가 아니라 `tags`와 `[[링크]]`로 한다.
폴더로 나누면 한 페이지가 한 곳에만 속하게 되는데, 지식은 원래 여러 곳에 걸쳐 있다.

## type 값

| 값 | 쓰는 경우 | 예 |
|---|---|---|
| `concept` | 개념·원리 | "SQL Injection이란" |
| `howto` | 실행 절차 | "Burp Suite 프록시 설정" |
| `reference` | 찾아보는 자료·목록 | "자주 쓰는 nmap 옵션" |
| `log` | 시점이 있는 기록 | "2026-09 CTF 참가 기록" |
| `moc` | 다른 페이지를 묶는 목차 | "웹 보안 인덱스" |
| `output` | 외부용 산출물 | `Output/` 전용 |

## status 값 — 신뢰도

| 값 | 의미 | AI가 쓰는 방식 |
|---|---|---|
| `seed` | 메모 수준. 검증 안 됨 | 참고만. 근거로 인용 금지 |
| `draft` | 정리됐으나 검증 부족 | 인용 시 "검증 필요" 명시 |
| `stable` | 검증 완료 | 근거로 자유롭게 인용 |

`source`가 비어 있으면 `stable`로 올리지 않는다.

## 특수 frontmatter 키

| 키 | 의미 |
|---|---|
| `pinned: true` | 내가 손으로 쓴 페이지. 자동 재컴파일 대상에서 제외 |
| `aliases: []` | 같은 주제를 부르는 다른 이름·약어·영문명. **중복 페이지를 막는 1차 방어선** |
| `description` | 한 줄 요약(90자 이내). 목록·대시보드·그래프에서 제목 옆에 보인다 |
| `needs_source: true` | 근거가 얇아 보강이 필요한 페이지. 출처가 2개가 되면 제거한다 |
| `contested: true` | 미해결 모순이 있는 페이지. 본문에 `> [!conflict]`가 반드시 함께 있어야 한다 |
| `contradictions: []` | 충돌하는 상대 페이지 이름. **양쪽에 서로를 적는다** |
| `archived: YYYY-MM-DD` | 폐기일. `_archive/`로 옮길 때 기록 |
| `superseded_by:` | 이 페이지를 대체한 페이지 이름 |

`aliases`가 중요한 이유: 제목만 비교하면 "SQL Injection"과 "SQLi"가 다른 주제로 보인다.
새 페이지를 만들기 전 검색은 제목뿐 아니라 `aliases`까지 대조해야 한다.

## 연구 축 태그 (필수)

모든 위키 페이지는 두 축 중 하나 이상의 태그를 단다. 어디에도 안 걸리면 수집 우선순위가 낮은 자료다.

| 태그 | 축 |
|---|---|
| `#ai-for-security` | AI를 활용해 보안을 수월하게 하는 방법 |
| `#securing-ai` | AI 자체를 지키는 것 |
| `#both` | 두 축에 걸치는 자료 |

축 판단이 애매하면 임의로 정하지 말고 나에게 물어라. 근거는 [[나의 핵심 맥락]]에 있다.

## 주제 태그 (`topic/*`)

축과 **다른 차원**이다. 축은 "AI와 보안의 관계 방향"이고, 주제는 "무엇에 관한 것인가"다.
그래서 한 자료가 축 1개 + 주제 여러 개를 가질 수 있다.

```yaml
axis: securing-ai
tags:
  - raw/article            # 매체
  - 주제/프롬프트-인젝션    # 주제
  - 주제/에이전틱-AI
```

- **반드시 `tags` 필드 안에 넣는다.** `topic:` 같은 별도 필드로 두면 Obsidian이
  태그로 인식하지 않아 **태그 창에 나오지 않는다**
- 형식: **`주제/한국어-하이픈`**. 공백은 금지다 (Obsidian 태그 제약)
- **고유명사·약어는 원문 표기를 유지한다.** 한국어로 옮기면 검색이 안 되거나 뜻이 흐려진다

| 유지 | 예 |
|---|---|
| 제품·도구·시스템 이름 | `주제/Sysmon` `주제/Zotero` `주제/Auto-Prov` |
| 정착된 약어 | `주제/LLM-활용` `주제/APT-탐지` `주제/DSPM` `주제/RAG` |
| 표준·분류체계 | `주제/STIX` `주제/ATT&CK` |

  한국어로 널리 쓰이는 말은 한국어로 쓴다 — `주제/프롬프트-인젝션`(O) / `주제/Prompt-Injection`(X)
- **기존 태그를 먼저 재사용한다.** 비슷한 태그가 늘어나면 폴더보다 못해진다
- 주로 `raw/`용이다. 위키 페이지는 제목과 `aliases`로 찾히므로 필수가 아니다

### 왜 축은 영어이고 주제는 한국어인가

| | 축 | 주제 |
|---|---|---|
| 개수 | 2~3개 고정 | 계속 늘어남 |
| 타이핑 | 거의 안 함 (구조용) | 자주 함 |
| 한국어로 쓰면 | **"AI 보안"이 두 뜻이라 모호해짐** | 문제 없음 |

축은 한국어가 **애매해서** 영어를 쓰고, 주제는 한국어가 **편해서** 한국어를 쓴다.
태그에는 `aliases`가 없어 표기가 하나뿐이므로, 실제로 검색할 언어로 적어야 한다.

주제 태그가 있으면 Obsidian **태그 창**에서 폴더처럼 훑을 수 있다. 폴더와 달리 **한 파일이 여러 주제에 동시에 속한다.**

## 인용 참조

`raw/papers/` `raw/books/` `raw/videos/` 자료를 근거로 쓰는 페이지는
`source`에 **경로가 아니라 인용키**를 적는다 (예: `kim2024llmsec`).

책·영상을 인용할 때는 **위치 표기(locator)를 함께 붙인다.**

| 매체 | 표기 예 |
|---|---|
| 논문 | `(kim2024llmsec, §3.2)` |
| 책 | `(stallings2023netsec, p.147)` |
| 영상 | `(computerphile2023sqli, 04:12)` |

locator 없는 책·영상 인용은 나중에 검증할 수 없다. 서지정보 형식은 `raw/CLAUDE.md`에 있다.

## 파일명

- 검색할 때 칠 말 그대로 쓴다. `SQL Injection.md` (O) / `20260901_sqli_v2.md` (X)
- 번호·날짜 접두사를 붙이지 않는다. 정렬은 옵시디언이 한다.
- 이름 변경은 반드시 옵시디언 안에서 한다 (링크가 따라옴). 탐색기에서 바꾸면 깨진다.
### 축 접두어 (필수)

`wiki/` 페이지 파일명은 **`(축)` + 공백 + 제목** 형식이다.

| 접두어 | 축 태그 | 뜻 |
|---|---|---|
| `(AI활용)` | `ai-for-security` | AI를 **도구로 써서** 보안을 한다 |
| `(AI보호)` | `securing-ai` | AI **자체를 보호 대상**으로 삼는다 |
| `(공통)` | `both` | **두 축 모두** 해당한다 |
| `(기타)` | 없음 | **어느 축에도 해당하지 않는다** (예: 드론 GPS 스푸핑) |

```
(AI활용) 프로베넌스 그래프
(AI보호) 프롬프트 인젝션
```

> [!warning] 대괄호 `[ ]`를 쓰지 마라
> 파일명에 `[ ]`가 들어가면 위키링크가 `[[[AI활용] 제목]]`처럼 3중으로 겹친다.
> Obsidian이 노트 이름에서 피하라고 권하는 문자가 `[ ] # ^ |`다. **소괄호를 쓴다.**

- **파일 탐색기에서 축별로 묶여 정렬**된다. 이게 접두어를 쓰는 주된 이유다
- `title:` frontmatter에는 **접두어 없이** 제목만 적는다. 접두어는 분류용이고 제목이 아니다
- **미생성 링크(`[[아직 없는 페이지]]`)에는 접두어를 붙이지 않는다.** 축이 확정되지 않았기 때문이다.
  페이지를 만들 때 접두어를 정하고 그 링크들을 함께 갱신한다
- 이름 변경은 반드시 **옵시디언 안에서** 한다. 링크가 자동으로 따라간다

## 페이지를 쪼개는 기준

- `## 한 줄 요약`을 한 문장으로 못 쓰겠으면 주제가 두 개다. 쪼갠다.
- 화면 3개를 넘어가면 하위 페이지로 분리하고 `moc`로 묶는다.
