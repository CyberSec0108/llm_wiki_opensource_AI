# lint — 위키 건강검진

**보고가 목적이다. 발견 즉시 고치지 마라.** 무엇을 / 어디서 / 어떻게 고칠지 제안하고, 실행 여부는 사용자가 정한다.

## 스캔 전 제외 규칙 (먼저 읽어라)

이걸 안 지키면 오탐이 쏟아져 보고서를 못 쓴다.

| 제외 대상 | 이유 |
|---|---|
| `CLAUDE.md`, `templates/` | frontmatter **예시**를 규칙으로 오인함 |
| 인라인 코드 안의 `[[링크]]` | 백틱 안 위키링크는 Obsidian이 링크로 만들지 않는다. 설명용 예시다 |
| `index.md`의 "아직 없는 페이지" 목록 | **의도적** 미생성 링크다. 깨진 링크가 아니라 할 일 목록이다 |
| `pinned: true` 페이지 | 사용자가 손으로 쓴 페이지. 갱신 제안만 하고 수정 대상에 넣지 마라 |
| `wiki/_archive/` | 폐기된 페이지. 링크·index·고아 검사 대상이 아니다 |
| `wiki/index.md`, `wiki/log.md` | 운영 파일. 내용 체크(마커·axis·한 줄 요약·원문밖)의 **대상이 아니라 기준**이다. 본문에 규칙 예시 문자열이 들어 있어 그대로 검사하면 오탐이 난다 |
| `wiki/_archive/README.md` | 폴더 설명서이지 폐기된 페이지가 아니다. 체크 28 제외 |

## 8가지 체크 (심각도순)

### 🔴 Error — 반드시 수정

**1. 깨진 wikilink**
존재하지 않는 페이지를 가리키는 링크. 단 **`index.md`의 "아직 없는 페이지"에 등록된 것은 제외** — 그건 정상 워크플로다.
→ 미등록 깨진 링크만 Error다. 오타이거나 index 등록을 빠뜨린 것이다.

**2. index.md와 실제 페이지의 불일치**
- 실제 페이지가 있는데 index에 없음
- index에 있는데 실제 페이지가 없음
- index의 `(status)` 표기가 페이지의 실제 `status`와 다름

### 🟡 Warning — 수정 권장

**3. 모순된 내용이 있는 페이지 쌍**
같은 주제를 다르게 서술하는 두 페이지. **어느 쪽이 맞는지 판정하지 마라.** 양쪽 소스를 모두 인용해 보여주고 사용자에게 묻는다.

**4. 고아 페이지 (inbound 링크 0)**
아무도 링크하지 않는 페이지. 어느 MOC에 붙일지 제안한다.

**5. stub 후보**
여러 페이지에서 **3회 이상 언급되는데 자체 페이지가 없는 개념.** 만들 가치가 있다는 신호다.

**6. 오래된 정보 (stale)**
- `updated`가 6개월 이상 지난 페이지
- 근거 자료보다 오래된 페이지 (새 raw가 들어왔는데 반영 안 됨)
- `AI 모델 통제 이탈 사례`처럼 시점이 중요한 `type: log` 페이지

### ℹ️ Info — 있으면 좋음

**7. 빠진 크로스레퍼런스**
서로 관련 있는데 링크가 없는 페이지 쌍. 같은 `tags`를 갖거나 서로의 제목·`aliases`를 본문에 언급하는데 링크가 없는 경우.

**8. raw에 있지만 미인제스트**
```
grep -rl "^ingested: false" raw/ --include=*.md | grep -v "CLAUDE.md"
```

## 이 볼트 고유 체크 (위 8개에 추가)

우리 규칙에서만 나오는 것들이다. 심각도를 함께 표시한다.

| # | 체크 | 심각도 |
|---|---|---|
| 9 | `source`가 비어 있는데 `status: stable`인 페이지 | 🔴 |
| 10 | `axis` 태그(`ai-for-security`/`securing-ai`/`both`)가 없는 위키 페이지 | 🟡 |
| 11 | raw 원본의 `why`와 `axis`가 어긋남 — 특히 "AI 보안"의 두 뜻 혼동 | 🔴 |
| 12 | `raw/papers` `books` `videos`인데 `cite_key`가 빈 파일 | 🟡 |
| 13 | 책·영상을 인용하면서 locator(`p.147`, `04:12`)가 없는 서술 | 🟡 |
| 14 | `index.md`의 줄이 120자를 넘음 | 🟡 |
| 15 | `## 한 줄 요약`이 없거나 두 문장 이상인 페이지 | 🟡 |
| 16 | `derived: true` 페이지를 근거로 또 파생된 페이지 | 🟡 |
| 17 | `needs_source: true`인데 아직 출처가 1개인 페이지 | ℹ️ |
| 18 | 17번 중 `updated`가 **3개월 이상** 지난 페이지 → **병합 제안** | 🟡 |
| 19 | `원문 밖` 절이 `원문 요약` 절보다 긴 페이지 (측정 조건은 아래) | 🟡 |
| 20 | `^[raw/...]` 마커가 frontmatter `source`에 없는 경로를 가리킴 | 🔴 |
| 21 | `source`가 2개 이상인데 `^[raw/...]` 마커가 하나도 없는 페이지 | 🟡 |
| 22 | `contested: true`인데 본문에 `> [!conflict]`가 없음 (또는 그 반대) | 🔴 |
| 23 | `contradictions`에 적힌 상대 페이지가 나를 되짚지 않음 (한쪽만 기록) | 🔴 |
| 24 | `contested`/`contradictions` 필드 자체가 없는 페이지 | 🟡 |
| 25 | 실재 페이지로 가는 링크가 **2개 미만**인 페이지 (`index`·`log` 제외) | 🔴 |
| 26 | 활성 페이지가 `_archive/` 안의 페이지를 링크함 | 🔴 |
| 27 | `_archive/` 페이지가 `index.md`에 등록돼 있음 | 🔴 |
| 28 | `archived` 또는 `superseded_by` 없이 `_archive/`에 있는 파일 | 🟡 |

17~19번은 **위키가 원본보다 커지는 것**을 막는 장치다. 실제로 팽창률이 92%까지 간 적이 있다.
17번 페이지에 출처가 2개가 되면 `needs_source`를 제거하라고 제안한다.

### 19번 측정 조건 (지키지 않으면 전부 오탐이다)

- **`## 원문 요약`으로 시작하는 절을 전부 합산한다.** 출처가 여럿이면 `## 원문 요약 — ahnlab`처럼
  나뉜다. 첫 절만 재면 멀쩡한 페이지가 위반으로 잡힌다.
- **두 절이 모두 없는 페이지는 검사 대상이 아니다.** MOC와 `type: log` 페이지는 이 구조를 쓰지
  않으므로 0B로 계산돼 무조건 위반이 된다.
- **17번이 이미 걸린 페이지는 보고하지 않는다.** 아래 참조.

**19번을 17번과 겹쳐 보고하지 마라.** 둘은 원인이 다르다.

| | 원인 | 처방 |
|---|---|---|
| 17번만 걸림 | 출처가 얇다 | **자료를 붙인다.** 설명을 지우지 않는다 |
| 19번만 걸림 | 출처는 충분한데 **내 설명이 과하다** | 내 정리를 줄인다 |
| 둘 다 걸림 | 출처가 얇다 (같은 원인) | **17번으로만 다룬다.** 19번은 보고하지 않는다 |

근거가 얇은 페이지에서 설명을 깎으면, 사용자가 요구한 "개념부터 상세히"를 지표 때문에 훼손하게 된다.
`context/나의 핵심 맥락.md`의 설명 방식 규칙이 우선한다.

11번은 실제로 발생한 적이 있다. 한국어 "AI 보안"이 두 뜻을 다 담아 헷갈린다.

```
Security FOR AI    = securing-ai       AI를 지킨다
AI FOR Security    = ai-for-security   AI로 보안한다
```

## 보고 형식

심각도별로 묶어 표로 낸다. 각 항목에 **무엇이 / 어디서 / 어떻게 고칠지** 세 가지가 다 있어야 한다.

```
## 🔴 Error (n건)

| # | 무엇이 | 어디서 | 어떻게 고칠지 |
|---|---|---|---|
| 1 | [[DSPM]] 링크가 깨짐 (index 미등록) | wiki/AI 시스템 보안.md:42 | index의 "아직 없는 페이지"에 추가하거나 페이지 생성 |
```

마지막에 **한 줄 총평**과 **우선 처리 3건**을 제시한다. 전부 고치라고 하지 마라 — 무엇부터인지가 더 유용하다.

## 수정 실행

사용자가 승인한 항목만 고친다.

- 여러 파일을 한 번에 옮기거나 이름을 바꾸기 전에 **다시 확인**받는다 — 링크가 깨진다
- 모순(3번)은 **혼자 판정하지 마라.** 양쪽을 남기고 `> [!conflict]`로 표시한다
- `raw/`는 `ingested` 외 수정 금지. 11번을 발견해도 **보고만** 하고 허락을 받는다
- 수정했으면 `wiki/log.md`에 `lint` 또는 `fix`로 append한다

## 하지 말 것

- 승인 없이 수정하기
- 의도적 미생성 링크를 깨진 링크로 보고하기
- 코드 스팬 안의 `[[예시]]`를 링크로 세기
- 모순을 혼자 판정하기
- "전부 고쳐야 합니다" 식의 우선순위 없는 보고
