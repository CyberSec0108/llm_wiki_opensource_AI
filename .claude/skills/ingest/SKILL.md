# ingest — 원본을 위키로 컴파일

형식 규칙은 여기에 다시 적지 않는다. **작업 전에 반드시 읽는다.**

- `raw/CLAUDE.md` — 원본 frontmatter, 불변 규칙, 인용키
- `wiki/CLAUDE.md` — 페이지 형식, 중복 방지 절차, 충돌 처리
- `context/나의 핵심 맥락.md` — 연구 축, 지식 경계, 설명 방식

## 0. 대상 선정

인자가 있으면 그 파일을, 없으면 `raw/`에서 **`ingested: false`인 파일**을 찾는다.

**스캔에서 제외할 것**: `CLAUDE.md`, `templates/`.
이 파일들은 frontmatter **예시**에 `ingested: false`를 포함하고 있어 그냥 스캔하면 오탐이 난다.

```
grep -rl "^ingested: false" raw/ --include=*.md | grep -v "CLAUDE.md"
```

- 여러 개면 목록을 보여주고 **어느 것부터 할지 묻는다.** 임의로 정하지 마라.
- 한 번에 **한 파일씩** 처리한다. 사용자가 "전부"라고 명시하면 그때 연속 처리한다.

## 1. 원본 읽기

`why` `axis`가 비어 있으면 **먼저 묻는다.** 추측해서 채우지 마라.

**`why`와 본문이 어긋나면 반드시 지적한다.** 특히 `axis` 오분류를 그냥 넘기지 마라.

```
Security FOR AI    = securing-ai       AI를 지킨다
AI FOR Security    = ai-for-security   AI로 보안한다
```

한국어 "AI 보안"은 두 뜻을 모두 담아 헷갈리기 쉽다. 제목이 아니라 **본문이 무엇을 보호 대상으로 삼는지**로 판단한다.

### 주제 태그 확정

담을 때 적은 주제 태그는 **글을 다 읽기 전에 적은 것**이라 부정확할 수 있다. 본문을 읽었으니 여기서 다듬는다.

1. `raw/` 전체에서 **이미 쓰이고 있는 `주제/*` 목록을 먼저 본다**
2. 맞는 게 있으면 **재사용한다.** 새 태그는 맞는 게 없을 때만 만든다
3. 최종안을 제시하고 **승인을 받은 뒤** `tags` 필드에 추가한다 (별도 필드가 아니다)

비슷한 태그(`주제/프롬프트-인젝션`과 `주제/인젝션`)가 늘어나면 태그가 폴더보다 못해진다.
형식은 **`주제/한국어-하이픈`**. 사용자가 한국어로 검색하므로 영문 태그를 쓰지 마라.

`raw/`의 본문과 서지정보는 수정하지 않는다. 틀렸으면 고치지 말고 보고하고 허락을 받는다.

## 2. 소스 요약 제시

위키에 쓰기 **전에** 사용자에게 먼저 보여준다.

- **핵심 주장** — 이 글이 실제로 말하는 것. 3~5개
- **다루는 개념** — 위키 페이지가 될 후보
- **등장 엔티티** — 도구·조직·인물. 지금은 기록만, 페이지로 만들지 않는다

원본에 없는 내용을 넣지 마라. 추론이면 `> [!inference]`로 표시한다.

## 3. 사용자에게 묻기

**답을 받기 전에 `wiki/`를 건드리지 마라.** 이 단계를 건너뛰면 목적 없는 요약이 된다.

1. (원본의 "내가 표시한 부분"이 비어 있을 때만)
   **이 글에서 가장 중요하게 본 대목은 어디야?**
2. **지금 하는 일과 어떻게 연결돼?** — `context/지금 하는 일.md`를 읽고 관련 항목을 짚어 제시한다
3. **이걸로 뭘 해보고 싶어?** — 참고용인지, `Output/`으로 갈 재료인지

`why`가 이미 채워져 있으므로 "왜 캡처했어?"는 **묻지 않는다.** 대신 `why`를 인용하며 시작한다.

## 4. 기존 페이지 먼저 찾기

**갱신이 생성보다 항상 우선한다.** 절차는 `wiki/CLAUDE.md`의 "새 페이지를 만들기 전에"를 그대로 따른다.

`index.md` → 본문 검색 → `aliases` 순. 한국어·영어·약어를 모두 시도한다.

## 5. 위키 반영

원본 종류에 따라 결과물이 다르다.

| 원본 | 만들 것 |
|---|---|
| `papers/` `books/` `videos/` | **소스 페이지**(그 자료의 주장 정리) + 개념 페이지 |
| `articles/` `writeups/` | **개념 페이지만.** 소스 페이지를 만들지 않고 개념 페이지에 흡수한다 |
| 엔티티(도구·조직·인물) | **만들지 않는다.** 같은 이름이 페이지 3곳에 나오면 그때 제안한다 |

각 페이지에 반드시 넣을 것:

- `source` — `articles/`는 경로, 인용 대상은 `cite_key`
- `axis` 태그 (`#ai-for-security` / `#securing-ai` / `#both`)
- 책·영상 인용은 locator 필수 — `(cite_key, p.147)` `(cite_key, 04:12)`
- 근거가 하나뿐이면 `status`는 `draft`를 넘지 않는다

기존 서술과 **모순**되면 덮어쓰지 말고 둘 다 남긴 뒤 `> [!conflict]`로 표시하고 **묻는다.** 판정하지 마라.

## 6. 마무리

1. `wiki/index.md` — 새 페이지는 한 줄 추가(120자 이내), 갱신은 기존 줄 수정
2. `wiki/log.md` — 맨 아래 한 줄 추가. **기존 줄 수정 금지**
   - 새 페이지를 만들었으면 **왜 기존 페이지에 못 넣었는지**를 함께 적는다
3. 원본의 `ingested`를 `true`로, 승인받은 주제 태그를 `tags`에 반영한다
4. 사용자에게 보고: 만든 페이지 / 갱신한 페이지 / 남은 미처리 파일 수

## 하지 말 것

- 3단계 질문을 건너뛰고 바로 위키에 쓰기
- 기존 페이지를 안 찾고 새로 만들기
- 원본에 없는 사실을 위키에 넣기
- `raw/` 본문이나 `ingested` 외 필드를 고치기
- 모순을 혼자 판정하기
