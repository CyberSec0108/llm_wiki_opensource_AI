# wiki/ — 컴파일된 위키 계층

여기 있는 페이지는 **파생물**이다. `raw/`에서 컴파일되며, 전부 지워도 원본에서 다시 만들 수 있어야 한다.
그래서 **원본에 없는 사실을 여기서 처음 만들어내면 안 된다.**

## 페이지 형식 (필수)

```yaml
---
title:
aliases: []    # 같은 주제를 부르는 다른 이름·약어·영문명. 중복 페이지를 막는 장치
type: concept | howto | reference | log | moc
status: seed | draft | stable
source:        # raw/ 기준 경로 또는 URL. 여러 개면 리스트
updated: YYYY-MM-DD
contested: false   # 이 페이지에 미해결 모순이 있는가
contradictions: [] # 충돌하는 다른 페이지 이름. 없으면 빈 리스트
description: ""    # 한 줄 요약과 같은 내용. 목록·대시보드에서 제목 옆에 보인다
tags: []
---

## 한 줄 요약
(이것만 읽고 페이지를 펼칠지 판단할 수 있어야 한다)
```

- `type`·`status` 값의 의미는 `context/위키 규약.md`를 따른다. 여기에 다시 적지 않는다.
- `source`가 비어 있으면 `status`를 `stable`로 올리지 않는다.
- 내용을 고쳤으면 `updated`를 반드시 갱신한다.
- `description`은 `## 한 줄 요약`과 같은 내용을 90자 이내로 적는다. 목록·대시보드에서 제목 옆에 보인다.
- **파일명은 `(축)` + 공백 + 제목이다** — `(AI활용)` / `(AI보호)` / `(공통)` / `(기타)`.
  **대괄호를 쓰지 마라** — 위키링크 문법과 겹친다. `title:`에는 접두어 없이 제목만 적는다.
  상세는 `context/위키 규약.md` 참조.

## 새 페이지를 만들기 전에 (필수 절차)

**기존 페이지 갱신이 새 페이지 생성보다 항상 우선한다.**
새 페이지는 "기존 어디에도 안 들어간다"를 확인한 뒤의 마지막 수단이다.

건너뛰지 말고 이 순서를 밟는다.

1. `index.md`를 읽는다. 제목·요약에 겹치는 게 있는지 본다.
2. 후보가 없으면 `wiki/` 전체에서 핵심어를 검색한다. **한국어·영어·약어를 모두 시도한다.**
   예: `SQL Injection` / `SQLi` / `SQL 인젝션` / `인젝션`
3. `aliases`도 검색 대상이다. 제목만 보고 없다고 판단하지 마라.
4. 그래도 없으면 그때 새로 만든다.

### 새 페이지 대신 해야 하는 것

| 상황 | 조치 |
|---|---|
| 같은 주제, 다른 이름 | 기존 페이지 `aliases`에 이름을 추가하고 **거기에** 쓴다 |
| 기존 주제의 하위 갈래 | 기존 페이지에 섹션을 추가한다. 화면 3개를 넘으면 그때 분리 |
| 기존 주제의 새 사례·근거 | 기존 페이지에 덧붙이고 `source`에 원본을 추가한다 |
| 정말 다른 주제 | 새로 만들고 기존 페이지와 `[[링크]]`로 잇는다 |

새 페이지를 만들었으면 **왜 기존 페이지에 못 넣었는지**를 `log.md`에 한 줄로 남긴다.
이 한 줄을 못 쓰겠으면, 새로 만들 이유가 없었던 것이다.

## 개념 페이지 생성 기준 (넷을 모두 만족해야 한다)

| # | 기준 | 확인 방법 |
|---|---|---|
| 1 | 다른 페이지 **3곳 이상**에서 `[[링크]]`로 참조됨 | `index.md`의 "아직 없는 페이지" 또는 lint 체크 5 |
| 2 | 원본 근거가 **1,200 B 이상**이고, **정의 외에 사례·수치·절차 중 하나 이상**이 있다 | 원본의 해당 절 분량 |
| 3 | 실재 페이지로 가는 링크를 **2개 이상** 걸 수 있다 | |
| 4 | `## 한 줄 요약`을 **한 문장**으로 쓸 수 있다 | |

**하나라도 안 되면 미생성 링크로 남긴다.**

### 왜 1,200 B인가

실제 데이터로 정한 값이다. 이 볼트에서 얇은 페이지가 된 것과 적정한 것의 원본 근거 분량:

```
얇음   547 · 583 · 596 · 714 B      ← 용어사전 항목 하나 크기
적정   1,515 · 1,619 B
```

750~1,500 B 구간에는 사례가 없다. 그 사이에서 **보수적으로 위쪽**을 잡았다.
**용어사전 항목 하나 = 개념 페이지 하나로 잡으면 반드시 얇아진다.**

### 묶어서 만들기

개별로는 기준 미달인데 **같은 원본의 인접한 주제**면, 묶어서 한 페이지로 만들고
`aliases`에 각 이름을 넣는다. 나중에 자료가 쌓이면 그때 쪼갠다.

```
(AI보호) AI 보안 통제 개념
aliases: [제로 트러스트, 기계 신원, DSPM]
```

## 어떤 페이지를 만들 것인가

원본 종류에 따라 결과물이 다르다. 모든 원본이 소스 페이지를 갖는 것은 아니다.

| 원본 | 만들 것 | 이유 |
|---|---|---|
| `papers/` `books/` `videos/` | **소스 페이지** + 개념 페이지 | "이 자료가 무엇을 주장했나"가 인용 단위다 |
| `articles/` `writeups/` | **개념 페이지만** | 블로그 글은 인용 단위가 아니다. 개념 페이지에 흡수한다 |
| 엔티티(도구·조직·인물) | **만들지 않는다** | 같은 이름이 페이지 3곳에 나오면 그때 제안한다 |

소스 페이지를 남발하면 index가 원본 목록이 되어 버린다. 위키는 원본 목록이 아니라 **정리된 지식**이다.

## 컴파일 규칙

- 한 페이지 = 한 주제. `## 한 줄 요약`을 한 문장으로 못 쓰면 쪼갠다.
- **주장 단위 출처 마커**를 단다. 마커 값은 **반드시 frontmatter `source`에 이미 있는 것**이어야 한다.

| 원본 | 마커 형식 | 예 |
|---|---|---|
| `articles/` `writeups/` `notes/` | `^[raw/<폴더>/<파일>.md]` | `^[raw/articles/AI 보안의 시작....md]` |
| `papers/` `books/` `videos/` | `^[<cite_key>, <locator>]` | `^[mavroeidis2018sysmon, §4.1]` |

  - 인용 대상 원본은 **locator를 함께 적는다** — 논문은 절·그림·표, 책은 페이지, 영상은 타임스탬프.
  - 출처가 2개 이상인 페이지에서는 **필수**다. 어느 주장이 어느 출처인지 구분되지 않으면 인용할 수 없다.
  - 출처가 1개면 생략 가능하다. frontmatter만으로 모호하지 않기 때문이다.
- 원본에 없는 판단·추론은 `> [!inference]` 콜아웃으로 분리한다. 본문에 섞지 마라.
- 검증 안 된 서술은 `> [!unverified]`로 표시한다.
- 관련 페이지는 `[[링크]]`로 연결한다. **아직 없는 페이지도 링크한다** — 그게 다음 작업 목록이다.
- **모든 페이지는 실재하는 다른 페이지로 가는 링크를 2개 이상 가져야 한다.**
  - 자기 자신, 미생성 페이지, 인라인 코드 안의 예시는 세지 않는다.
  - 2개를 못 채우겠으면 **그 페이지를 만들 때가 아니다.** 고립된 지식은 위키가 아니라 메모다.
  - 예외는 `index.md`와 `log.md` 뿐이다 (운영 파일이지 지식 페이지가 아니다).
- 링크가 3개 이상 모이는 주제가 생기면 `type: moc` 페이지로 묶고 `index.md`에 올린다.

## 원문과 내 정리를 섞지 마라 (필수)

**이 위키가 실제로 무너졌던 지점이다.** 원본 2~3문장을 페이지로 만들면서 비교표·배경 설명을
덧붙이면, 페이지의 대부분이 원문에 없는 내용이 된다. 그러면 나중에 무엇을 인용할 수 있는지
알 수 없게 된다.

페이지를 이 구조로 쓴다.

```
## 한 줄 요약
## 원문 요약          ← 원본에 있는 것만. 여기서 새 사실을 만들지 마라
## 원문 밖 — 내 정리   ← 배경 설명·비교표·다른 페이지와의 연결
> [!inference] 로 시작하고, 원문에 없다는 것을 첫 줄에 밝힌다
## 관련
```

### 분량 점검

**`원문 밖` 절이 `원문 요약` 절보다 길면 멈추고 다시 생각한다.**
근거가 얇은데 페이지를 만들고 있다는 신호다. 이럴 때는 페이지 대신 **MOC의 표 행 + `aliases`** 로 남긴다.

목표: 위키 전체 분량이 원본 분량을 넘지 않는다. 위키는 압축된 지식이지 재작성이 아니다.

## 충돌 처리

새 원본이 기존 페이지와 **모순**되면:

1. 기존 서술을 지우지 마라.
2. 두 서술을 나란히 남기고 각각 `^[raw/...]` 마커를 단다.
3. `> [!conflict]` 콜아웃으로 표시한다.
4. **frontmatter를 갱신한다** — 콜아웃만으로는 기계가 찾을 수 없다.
   - `contested: true`
   - 다른 페이지와 충돌하면 `contradictions: [상대 페이지 이름]`을 **양쪽 모두에** 적는다
5. `log.md`에 기록하고, 어느 쪽이 맞는지 나에게 묻는다. **네가 판정하지 마라.**

모순이 해소되면 `contested: false`로 되돌리고 `contradictions`를 비운다.

## 손으로 고친 페이지

내가 직접 쓴 문단은 재컴파일 때 날아가면 안 된다.
frontmatter에 `pinned: true`가 있으면 **그 페이지는 자동 갱신 대상에서 제외**하고, 갱신이 필요하면 나에게 먼저 알려라.

## 페이지 폐기

페이지를 **지우지 마라.** `wiki/_archive/`로 옮긴다.

`raw/`가 불변이라 원본은 남지만, "내가 한때 이렇게 이해했다"는 기록은 페이지를 지우면 사라진다.

### 옮길 수 있는 경우

| 옮긴다 | 옮기지 않는다 |
|---|---|
| 다른 페이지가 이 내용을 **완전히 대체**함 | 근거가 얇음 → `needs_source: true`로 표시하고 자료를 붙인다 |
| 주제가 볼트 범위를 벗어남 | 오래됨 → `updated`를 갱신하고 내용을 고친다 |
| 잘못된 전제 위에 세워짐 | 링크가 적음 → 링크를 붙인다 |

**얇거나 오래됐다는 이유로 폐기하지 마라.** 그건 보강할 일이지 버릴 일이 아니다.

### 절차

1. frontmatter에 `archived: YYYY-MM-DD`와 `superseded_by: 대체 페이지 이름`을 추가한다
2. 파일을 `wiki/_archive/`로 옮긴다
3. **이 페이지를 가리키던 모든 링크를 대체 페이지로 돌린다.** 이걸 빠뜨리면 깨진 링크가 생긴다
4. `index.md`에서 해당 줄을 지운다
5. `log.md`에 `archive`로 기록하고 **폐기 이유**를 적는다

폐기된 페이지는 `query`의 근거가 아니다. `index.md`에 등록하지 않는다.

## 매 작업 후

- **새 페이지**: `index.md`에 한 줄 추가. 형식 `- [[페이지]] — 요약 (status)` — **줄 전체 120자 이내.**
- **기존 페이지 갱신**: index의 해당 줄에서 요약·status만 고친다. **줄을 새로 만들지 마라.**
- `log.md`에 한 줄 추가한다. **기존 줄은 절대 수정하지 않는다.**
